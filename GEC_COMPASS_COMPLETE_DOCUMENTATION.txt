1. EXECUTIVE OVERVIEW
--------------------------------------------------------------------------------
GEC Compass is a state-of-the-art, offline-first smart campus navigation and 
indoor localization platform engineered specifically for the sprawling campus 
of Government Engineering College Thrissur. 

The application solves the critical challenges of campus navigation:
1. Complex outdoor pathway networks between departments, hostels, and workshops.
2. Dynamic time-based gate schedule evaluations with spoken rerouting notices.
3. Fluid, smooth road polyline curve interpolation (Chaikin's Corner-Cutting algorithm).
4. GPS signal degradation and multipath errors inside multi-story academic blocks.
5. High-precision sub-meter campus grid addressing and seamless live location sharing.
6. Sensor-fused Pedestrian Dead Reckoning (PDR) and Visual Positioning (VPS) calibration.
7. Dedicated campus washroom/restroom facility discovery and management.
8. Crowd-contributed live updates for campus events and venue changes.

--------------------------------------------------------------------------------
2. ARCHITECTURE & CORE SUBSYSTEMS
--------------------------------------------------------------------------------
The application is structured into seven modular, decoupled subsystems:

1. Dynamic Road Network & Routing Engine (`routing_service.dart`):
   - High-precision topological graph navigation over verified campus pathways.
   - Real-time Dijkstra shortest path algorithm with road edge snapping.
   - Dynamic Gate Schedule Intelligence: evaluates open/closed operating hours, applies 5000m detour penalty for closed gates, and outputs verbal and visual alternative route notices.
   - Fluid Road Curve Smoothing (`smoothPolyline`): multi-pass Chaikin's corner-cutting algorithm creates organic, elegant road curvature while strictly preserving exact start and destination endpoints.
   - Offline boundary fallback routing when OSRM or network is unavailable.

2. Real-Time Dynamic Map Controller (`map_screen.dart`):
   - 60 FPS hardware-accelerated polyline rendering using `ValueNotifier`.
   - Real-time path shrinking behind the user as they advance along the route.
   - Spoken Turn-by-Turn voice guidance (TTS), spoken gate closure notifications, haptic alerts, and 20m advance warnings.
   - Multi-sample debounced off-route detection.

3. Sensor-Fused Pedestrian Dead Reckoning (PDR) (`pdr_service.dart`):
   - Native Android physical activity hardware step detector integration (`com.gec.compass/step_detector`).
   - Dynamic Weinberg step-length estimation based on peak-to-trough acceleration variance and cadence.
   - Low-latency circular Exponential Moving Average (EMA) magnetic compass heading filter.
   - Speed-weighted course bearing blending with high-speed GPS vectors.
   - Active GPS bias correction derived from differential VPS ground truth.
   - Sub-meter campus grid quantization to eliminate sensor jitter without losing curve geometry.

4. Visual Positioning System (VPS) Differential Relocalization (`vps_camera_screen.dart`, `vps_sensor_fusion.dart`):
   - Real-time camera visual scanning: QR anchors, OCR room signboards, and SLAM feature tracking.
   - Special VPS vs GPS Comparison Algorithm: computes vector displacement Δ = ||x_VPS - x_GPS||.
   - Dynamic GPS Multipath Bias Estimator: calculates spatial bias b = x_GPS - x_VPS and compensates subsequent GPS fixes.
   - Inverse-variance sensor fusion: w_VPS = var_GPS / (var_VPS + var_GPS).
   - Instant PDR drift reset and multi-floor level synchronization.

5. Campus Geodesic Grid Addressing System (`grid_addressing_service.dart`):
   - Inspired by Google Maps Plus Codes, customized specifically for GEC Thrissur campus geometry.
   - Converts coordinates into human-readable alphanumeric codes (e.g., `GEC-E074-N052` / `GEC-E074.4-N052.8`).
   - Powers frictionless live location sharing via WhatsApp, Telegram, SMS, or direct web deep links.
   - Instant Search Bar Resolution: typing any GEC Grid Code flies the camera directly to that exact campus spot.
   - Spatial bounds validation and sub-meter grid quantization.

6. Indoor Multi-Floor Navigation (`floor_mapping_screen.dart`):
   - Multi-floor elevation tracking and staircase ascent/descent step counters.
   - 2.5D visual floor layout mapping and room search.

7. Cloud-Synchronized POI Management (`data_service.dart`):
   - Real-time MongoDB and REST API synchronization for custom places, labs, washrooms, and gates.
   - In-app photo compression, Cloudinary linking, and gate schedule editing.

3. DETAILED FEATURE BREAKDOWN & HOW EVERYTHING WORKS
--------------------------------------------------------------------------------

================================================================================
A. ROAD NETWORK, TOPOLOGICAL GRAPH ROUTING & GATE SCHEDULE INTELLIGENCE
================================================================================
• Data Source: `assets/campus_roads.json`
  - 229 Topological Nodes & 257 Edges forming a single, 100% connected graph.
  - Covers every paved road, pedestrian walkway, hostel alleyway, canteen connector,
    and academic corridor across the entire GEC Thrissur perimeter.
  - Completely editable JSON structure for seamless future campus road extensions.

• Dynamic Gate Closure Detection & Verbal/Visual Announcements:
  - Real-world schedule checking for all gates (Main Gate 06:00 AM - 10:30 PM, South Gate 06:00 AM - 09:30 PM, East Gate 06:00 AM - 09:00 PM, plus custom added gates).
  - When the primary closer gate is closed at the current time, the router automatically selects the optimal OPEN alternative gate.
  - Generates explicit spoken notice via TTS: e.g., "Main Gate may be closed at this time. Rerouted via South Gate which is open."
  - Displays high-visibility Amber warning badge on top turn-by-turn guidance banner and snackbar alert.

• Fluid Road Curve Smoothing (`smoothPolyline`):
  - Applies multi-iteration Chaikin's Corner-Cutting algorithm over raw road segments.
  - Subdivides sharp polygon vertices into tangential bezier-like fillets with 22% tension factor.
  - Generates organic, smooth road curves while keeping start points and destination pins 100% locked.

• Single Optimal Route Selection:
  - Guarantees returning strictly ONE best path (avoiding clutter or confusing routes).
  - Uses geometric perpendicular projection to snap starting GPS coordinates and
    target destinations to the nearest walkable pathway edge.
  - Calculates the shortest Dijkstra distance through the road graph.

================================================================================
B. REAL-TIME NAVIGATION & DYNAMIC PATH SHRINKING
================================================================================
• 60 FPS Dynamic Path Shrinking:
  - The navigation polyline is wrapped in a `ValueListenableBuilder<List<LatLng>>` listening
    to `_routingPathNotifier`.
  - As the user walks forward, the traversed portion of the blue route polyline dynamically
    shrinks behind their position in real-time, without triggering full-screen widget rebuilds.

• Full-Polyline Nearest-Point Search:
  - Evaluates all vertices across the entire route to guarantee the user's progress is tracked
    even around sharp 90-degree building corners and multi-segment turns.

• 2-Sample Debounced Rerouting:
  - Prevents erratic route recalculations due to transient GPS jitter.
  - Rerouting triggers only if the user deviates > 20 meters from the current route across
    two consecutive sensor samples.

• Voice Turn-by-Turn Guidance (TTS):
  - Spoken audio instructions via FlutterTTS with automatic 20-meter advance warning before turns.

================================================================================
C. SENSOR-FUSED PEDESTRIAN DEAD RECKONING (PDR)
================================================================================
• Hardware Step Detector Stream:
  - Subscribes to native Android activity recognition step sensor (`com.gec.compass/step_detector`).
  - Fallback to high-rate user accelerometer peak-to-trough detection when native step sensor is unavailable.

• Dynamic Weinberg Stride Length Estimation:
  - Computes stride length dynamically: length = 0.45 * (accel_max - accel_min)^0.25.
  - Further frequency-compensated based on step cadence: length_adj = 0.38 + 0.16 * frequency.
  - Clamped to natural human biomechanical limits (0.48m - 0.92m).

• Circular EMA Compass & Gyroscope Fusion:
  - Smooths magnetic heading using trigonometric circular averaging.
  - Blends GPS course heading when walking speed > 0.8 m/s to eliminate magnetic interference.

• Active Differential GPS Bias Compensation:
  - Stores spatial bias offsets (Δlat, Δlng) generated during VPS optical relocalization.
  - Raw GPS fixes are corrected towards the calibrated coordinate system with smooth 90s exponential decay.

• Sub-Meter Grid Quantization:
  - Output coordinates are quantized to 0.2m grid increments using `GridAddressingService.snapToCampusGrid`,
    completely eliminating micro-jitter while preserving true trajectory curves.

================================================================================
D. VISUAL POSITIONING SYSTEM (VPS) & DIFFERENTIAL COMPARISON ALGORITHM
================================================================================
• Camera Visual Anchoring:
  - Real-time optical reticle scanning with target signboard reference picture-in-picture (PIP).
  - Multi-scheme QR payload decoding (`vps://room?name=...&lat=...&lng=...&floor=...&heading=...` and JSON).
  - SLAM feature point cloud density metrics and OCR room text matching.

• Special VPS vs GPS Comparison Algorithm:
  - Vector Difference Calculation: Δ = ||x_VPS - x_GPS||.
  - GPS Multipath Drift Detection:
    * If Δ > (3 * accuracy_GPS + 8m) or Δ > 25m, flags severe GPS multipath reflection.
    * Automatically snaps user location to visual anchor ground truth (±0.2m error bound).
    * Computes spatial bias: b_GPS = x_GPS - x_VPS.
  - Inverse-Variance Fusion Blending:
    * VPS variance: var_VPS = ((1 - conf_VPS) * 0.4 + 0.1)^2.
    * GPS variance: var_GPS = isMultipath ? 500.0 : max(accuracy_GPS, 2.0)^2.
    * Weight: w_VPS = var_GPS / (var_VPS + var_GPS) (clamped to 0.85 - 1.0).
    * Calibrated Position: x_calibrated = w_VPS * x_VPS + (1 - w_VPS) * x_GPS.
  - Full Handover to PDR & Map:
    * Resets PDR drift accumulator and dead-reckoning starting anchor.
    * Synchronizes multi-floor level.
    * Updates live map view and displays calibration HUD badge with offset compensation metrics.
